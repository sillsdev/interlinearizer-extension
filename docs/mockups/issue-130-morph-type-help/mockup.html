Morph-type indicator help — mockup

Three placements for a “what do these characters mean?” helper in the morpheme breakdown editor, modelled on the FieldWorks Insert Morpheme Breaks dialog. Static mockup for discussion on sillsdev/interlinearizer-extension#130 — nothing here is implemented.

A · Expandable section inside the editor
A help toggle in the panel header expands the break-character list in place, and the panel echoes back the type it read from each morpheme as you type. One floating layer, nothing to hover-hunt, and the expanded state can persist across opens. Costs vertical space while open.

Clitic, circumfix, particle and phrase take no indicator — they are told apart in the dictionary, not here.
B · Hover / focus card off the help icon
The editor keeps its current size; the list floats beside it on hover or keyboard focus, then goes away. Cheapest to glance at and closest to the “hoverable help icon” in the issue, but it stacks a second floating layer over an already-modal popover and is awkward to keep open while typing.

C · Docked side panel
A panel docked in the web view, toggled from the view options and independent of any one token. Room for every type plus prose, and it stays put while the user works through a passage. Costs horizontal space in an already-wide strip, and is the most work to build.
